# Codex handoff — Android → Google Play CI/CD

**Objective:** Implement a GitHub Actions pipeline that, on every push to `main`, builds a signed
Android App Bundle for `com.mbuchoff.voicechecklist` and uploads it to the Google Play **Internal
testing** track, using the **GitHub Actions run number as the Android `versionCode`**.

**Design source of truth:** read **[plan.md](./plan.md)** (approved) and the manual process it
automates, **[../publishing-android.md](../publishing-android.md)**. This handoff is self-contained —
you should not need any prior conversation.

---

## Repo facts you must internalize

- **Stack:** Expo SDK 55, React Native 0.83, TypeScript, expo-router. Package/applicationId
  `com.mbuchoff.voicechecklist`. Repo `mbuchoff/voice-driven-checklist`, default branch `main`.
  Toolchain the app build needs: **JDK 17**, Gradle 9.0.0, AGP 8.12.0, compileSdk 35,
  build-tools 35.0.0, **NDK 27.1.12297006**, CMake 3.22.1. Node is unpinned → use **Node 20**.
- **`android/` is gitignored and regenerated by `expo prebuild`.** Never hand-edit anything under
  `android/` — those files are ephemeral and will be overwritten. All native changes must be injected
  through an Expo **config plugin** or **`app.config.js`**.
- **Config source of truth is `app.json`** (static; there is no `app.config.js` yet). `app.json` has
  **no `android.versionCode`** today; `expo prebuild` currently defaults it to `1`.
- **Existing config plugin to mirror:** `plugins/withNotifeeMicrophoneForegroundService.js`. Note its
  patterns: `require('expo/config-plugins')`, string transforms on `modResults.contents`, an
  early-return idempotency guard, and a hard `throw new Error(...)` when an expected anchor is missing.
- **Tests:** `jest-expo` preset (`jest.config.js`), co-located `*.test.ts(x)` / `*.test.js`. Run with
  `npm test`. `transformIgnorePatterns` already allows `expo` packages, so requiring
  `expo/config-plugins` inside a test works.
- **Upload keystore** is at the repo root: `play-store-voice-checklist-upload - passphrase is <…>.jks`
  (gitignored via `*.jks`, not committed). Key alias is **`upload`**; the store and key passwords are
  the passphrase embedded in that filename. **Do not copy that passphrase into any committed file** —
  the pipeline reads it from a GitHub secret.

## House rules — follow strictly (from `AGENTS.md` / `CLAUDE.md`)

- **TDD is mandatory.** For each of the two code artifacts: write a failing test, run it and confirm it
  fails for the right reason, write the minimum code to pass, confirm green, refactor if needed.
- Make the **smallest reasonable change**; match surrounding style; YAGNI.
- **Do not commit unless explicitly asked.** If you are asked to commit: create a WIP branch first
  (never commit straight to `main`), never use `git add -A` without checking `git status`, and never
  skip pre-commit hooks.
- **Never print or commit secret values** (keystore passphrase, service-account JSON, base64 keystore).
- Root-cause over workaround. Test real logic, not mocks. Keep test output pristine.
- If a build.gradle anchor below does not match the freshly-generated file, **stop and report** —
  don't force a brittle edit. Re-derive the anchor from the actual generated file and note the drift.

## Step-by-step

### Step 1 — `app.config.js` (versionCode from run number)

1. **Test first** (`app.config.test.js`): require the module; with `process.env.ANDROID_VERSION_CODE =
   '42'`, calling it as `fn({ config: { android: {} } })` yields `android.versionCode === 42`; with the
   env var unset it falls back to `1`; and unrelated `config` keys are preserved. Reset the env var
   between cases.
2. **Implement** exactly as in plan.md §2 — a function `({ config }) => ({ ...config, android: {
   ...config.android, versionCode } })` where `versionCode` is `Number(process.env.ANDROID_VERSION_CODE)`
   when set else `config.android?.versionCode ?? 1`.
3. Sanity-check coexistence: `npx expo config --type public` (or a prebuild dry run) still resolves,
   and `app.json` remains the untouched base.

### Step 2 — `plugins/withReleaseSigningConfig.js` (release signing)

The generated `android/app/build.gradle` contains **exactly** this (captured from a real prebuild — use
it as your test fixture):

```groovy
    signingConfigs {
        debug {
            storeFile file('debug.keystore')
            storePassword 'android'
            keyAlias 'androiddebugkey'
            keyPassword 'android'
        }
    }
    buildTypes {
        debug {
            signingConfig signingConfigs.debug
        }
        release {
            // Caution! In production, you need to generate your own keystore file.
            // see https://reactnative.dev/docs/signed-apk-android.
            signingConfig signingConfigs.debug
            def enableShrinkResources = findProperty('android.enableShrinkResourcesInReleaseBuilds') ?: 'false'
            shrinkResources enableShrinkResources.toBoolean()
            minifyEnabled enableMinifyInReleaseBuilds
            proguardFiles getDefaultProguardFile("proguard-android.txt"), "proguard-rules.pro"
            def enablePngCrunchInRelease = findProperty('android.enablePngCrunchInReleaseBuilds') ?: 'true'
            crunchPngs enablePngCrunchInRelease.toBoolean()
        }
    }
```

1. **Test first** (`plugins/withReleaseSigningConfig.test.js`): import the plugin, call its inner
   `withAppBuildGradle` transform on the fixture string above (you can call the exported plugin with a
   minimal fake config `{ modResults: { language: 'groovy', contents: FIXTURE } }` via the
   `expo/config-plugins` test path, or factor the pure string transform into an exported helper and
   test that directly — the latter is simpler and preferred). Assert:
   - the `release` signingConfig block with the four `VOICE_CHECKLIST_UPLOAD_STORE_FILE /
     _STORE_PASSWORD / _KEY_ALIAS / _KEY_PASSWORD` references is present and guarded by
     `project.hasProperty('VOICE_CHECKLIST_UPLOAD_STORE_FILE')`;
   - the **release** buildType line is now `signingConfig signingConfigs.release`;
   - the **debug** buildType line is still `signingConfig signingConfigs.debug` (unchanged);
   - running the transform twice equals running it once (idempotent);
   - the transform throws if a required anchor is absent (feed it a stripped string).
2. **Implement** with two whitespace-tolerant regex replacements + an idempotency guard
   (`if (contents.includes('signingConfigs.release')) return contents;`) and a `throw` if either
   anchor is missing. Anchors:
   - **Add release signingConfig:** match the debug signingConfig's tail — `keyPassword 'android'`,
     its closing `}`, then the `signingConfigs` closing `}` immediately before `buildTypes {` — and
     insert the `release { … }` block (plan.md §2a) just inside the `signingConfigs` close.
   - **Repoint release buildType:** match the unique comment
     `// see https://reactnative.dev/docs/signed-apk-android.` followed by
     `signingConfig signingConfigs.debug`, and replace only that `signingConfig` line with
     `signingConfig signingConfigs.release`. (The `debug` buildType's identical line has no such
     preceding comment, so it is untouched.)
   Export shape: `module.exports = (config) => withAppBuildGradle(config, (c) => { c.modResults.contents
   = transform(c.modResults.contents); return c; });` — mirror
   `plugins/withNotifeeMicrophoneForegroundService.js`.
3. **Register** in `app.json`: append `"./plugins/withReleaseSigningConfig"` to `expo.plugins` (after
   `"./plugins/withNotifeeMicrophoneForegroundService"`).

### Step 3 — `.github/workflows/android-release.yml`

Create it verbatim from plan.md §3. Key correctness points:

- Trigger: `push: branches: [main]` **and** `workflow_dispatch`.
- `concurrency: { group: android-release, queue: max }` so newer pending releases do not replace
  older pending releases and only one release runs at a time.
- Restrict the workflow token to `permissions: { contents: read }`.
- Install the exact NDK/CMake/SDK: `yes | sdkmanager "ndk;27.1.12297006" "cmake;3.22.1"
  "platforms;android-35" "build-tools;35.0.0"`.
- Pin `android-actions/setup-android` to the v3.2.2 commit SHA
  `9fc6c4e9069bf8d3d10b2204b1fb8f6ef7065407`.
- Gate on `npm run lint`, `npm run typecheck`, `npm test`.
- Decode keystore from `ANDROID_KEYSTORE_BASE64` into `$RUNNER_TEMP/upload.jks`.
- Prebuild with `ANDROID_VERSION_CODE: ${{ github.run_number }}`.
- Build from `android/` with `./gradlew bundleRelease --no-daemon`, passing signing via
  `ORG_GRADLE_PROJECT_VOICE_CHECKLIST_UPLOAD_*` env (maps to the gradle project properties the plugin
  reads — keeps secrets out of `argv`/logs). Store file = `${{ runner.temp }}/upload.jks`.
- Upload the `.aab` as an artifact (so failed-upload runs still produce a downloadable bundle).
- Upload to Play with `r0adkll/upload-google-play` pinned to the v1.1.5 commit SHA
  `e738b9dd8f2476ea806d921b64aacd24f34515a5`, `track: internal`, `status: completed`,
  `packageName: com.mbuchoff.voicechecklist`.

### Step 4 — `.gitignore`

Append an ignore for a locally-saved service-account key, e.g. `*service-account*.json` (place it near
the existing `*.jks` line). Do not commit any secret.

## Acceptance criteria

- `npm test` passes, including the three new test files; output is pristine.
- `ANDROID_VERSION_CODE=999 npx expo prebuild --platform android --no-install --clean` yields
  `android/app/build.gradle` with `versionCode 999`, a `release` signingConfig block, and the release
  buildType referencing `signingConfigs.release`; the debug buildType still references
  `signingConfigs.debug`.
- Config plugin transform is idempotent and throws on missing anchors.
- The workflow file is valid YAML, matches plan.md §3, and pins third-party actions to SHAs.
- The workflow queues pending releases with `queue: max`.
- No secret value is committed anywhere.

## Out of scope (human-owned — do not attempt)

- Creating the Google Play service account / JSON key and Play Console permissions.
- Adding the five GitHub Actions secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
  `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`, `PLAY_SERVICE_ACCOUNT_JSON`).
- Any Play Console UI action. The first two CI runs (versionCode 1, 2) are expected to fail at the
  upload step because those codes already exist on Play; runs ≥ 3 publish.
- Direct manual allocation of a new version code or upload of a locally-built release. After CI
  cutover, human-requested releases use `workflow_dispatch` so the workflow remains the only version
  code authority.
